# 01 业务目标与指标定义（目标 1 交付）

> 机器可读版本见 `data/kb/metrics.yaml`（治理层、评估层、前端共同消费），完整性校验：`python scripts/validate_metrics.py`

## 1. 业务目标说明

某全国连锁零售企业（50 家门店、500 个 SKU、多区域、会员制）建设**经营决策 Agent**，主线为 **目标—感知—诊断—决策—执行—治理—评估** 七步闭环：

| 目标 | 内容 | 改善指标 |
|---|---|---|
| G1 保销售 | 减少缺货、客诉、竞品冲击导致的销售损失 | 销售额、销量、缺货率、客诉率 |
| G2 提效率 | 更快发现异常、更快补货，降低资金占用 | 异常发现时效、库存周转天数 |
| G3 增会员 | 精准触达与促销，提升复购与投放效率 | 会员复购率、促销 ROI |
| G4 控风险 | Agent 可控可审计，高风险动作 100% 人工审批 | 根因准确率、建议采纳率、自动执行成功率、高风险审批合规率 |

**系统边界**：所有数据均由 Mock 系统生成（可重复、有随机种子）；Agent 只读事实、只依据工具返回数据推理；所有写操作幂等、可 dry-run、可审计、可补偿；高风险动作必须人工审批；禁止动作直接拒绝。

## 2. 用户角色（权限矩阵摘要）

| 角色 | 代码 | 权限级 | 数据范围 | 职责 |
|---|---|---|---|---|
| 区域经理 | region_manager | L2 | 区域 | 区域总览、跨店调拨确认 |
| 门店店长 | store_manager | L2 | 本店 | 本店异常与建议、补货申请 |
| 供应链计划员 | supply_planner | L2 | 全局 | 补货/调拨执行、安全库存 |
| 会员运营 | member_ops | L2 | 全局 | 促销与会员触达、ROI 跟踪 |
| 客服主管 | cs_supervisor | L2 | 全局 | 客诉处理、回访任务 |
| 总部运营 | hq_ops | L2 | 全局 | 全局指标、复盘、知识库 |
| 风控审批人 | risk_approver | L3 | 全局 | 高风险动作审批、全量审计 |
| Agent 服务身份 | agent_service | L2 | 全局 | 自动执行上限 L2，L3 转审批，L4 拒绝 |

权限等级：L0 只读 / L1 建议 / L2 低风险写入 / L3 高风险写入 / L4 禁止（详见目标 8 治理层）。

## 3. 核心场景（触发条件 → 影响指标 → 建议动作 → 风险 → 审批）

| 场景 | 触发条件 | 影响指标 | 建议动作 | 风险 | 审批要求 |
|---|---|---|---|---|---|
| 销量骤降 | 门店-SKU 日销量 < 28 天滚动中位数 × 60%，连续≥2 天 | 销售额、销量、缺货率 | 补货/调拨/促销/客服跟进 | 中 | 视动作：补货自动，促销按规则 |
| 销量骤升 | 门店-SKU 日销量 > 基线 × 180%，连续≥2 天 | 销售额、促销ROI、缺货率 | 补货/会员触达 | 低 | 补货自动；新增促销须审批 |
| 缺货 | 库存≤安全库存 或 =0 且近 7 天有销售 | 缺货率、销售额、周转 | 补货、调拨 | 低 | 常规补货自动；跨区域调拨审批 |
| 临期 | 剩余保质期<30% 且库存>近14天销量 | 毛利率、周转 | 折价促销、会员触达 | 中 | 折扣≤10% 自动；>10% 审批 |
| 会员流失 | 门店 30 天复购率环比降>20% | 复购率、销售额 | 会员触达、促销 | 中 | 小额券自动；超预算审批 |
| 客诉上升 | 客诉率 > 基线 2 倍，连续≥3 天 | 客诉率、销售额、复购 | 客服跟进、临期折价 | 中 | 回访自动；赔偿人工 |
| 竞品促销 | 竞品同品类促销 + 本店品类销量降>15% | 销售额、销量 | 促销、价格跟踪 | 高 | 价格变更必须审批 |
| 天气影响 | 天气突变 + 品类销量同步偏移 | 销售额、销量 | 补货/调拨/陈列 | 低 | 按动作本身等级 |

## 4. 指标字典（12+1 项）

业务指标（数据源=Mock 系统表）：销售额、销量、毛利率、缺货率、库存周转天数、促销 ROI、会员复购率、客诉率。
Agent 指标：异常发现时效、根因定位准确率、建议采纳率、自动执行成功率。
治理指标：高风险审批合规率（目标 100%）。

每项指标的定义/公式/数据源/粒度见 `data/kb/metrics.yaml:metrics`。
